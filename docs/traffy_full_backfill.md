# ดึงและตรวจข้อมูล Traffy ย้อนหลังทั้งช่วง

รอบส่งมอบนี้กำหนดช่วงวันที่ไทยเป็น **2022-06-01 ถึง 2026-11-08 รวม 1,622 วัน**
วันสิ้นสุดเป็นเมื่อวาน ณ วันที่เริ่มงาน จึงคงช่วงนี้ไว้แม้งานจะรันข้ามเที่ยงคืน
การดาวน์โหลดทำบนเครื่อง ส่วนการตั้งค่า AWS ถูกเลื่อนไว้ตามคำขอของเจ้าของงาน

## เริ่มหรือรันต่อ

```powershell
python -X utf8 -u -m scripts.run_traffy_backfill --start 2022-06-01 --end 2026-11-08
```

ตัวรันตรวจข้อมูลที่มีอยู่ก่อน แล้วดึงเฉพาะวันที่ขาดหรือไฟล์ตรวจสอบไม่ผ่าน
ทำพร้อมกันได้ไม่เกินสี่วัน และเริ่มคำขอ API ห่างกันอย่างน้อย 0.5 วินาทีทั้งงานรวมกัน
แต่ละวันใช้ตัวดึงเดิม จึงยังได้ข้อมูลดิบและกติกาตรวจสอบชุดเดิม
วันที่ผิดพลาดจะถูกลองใหม่ไม่เกินสามรอบ เมื่อครบแล้วยังมีช่องว่างจะระบุว่า `INCOMPLETE`
ไม่ทำเครื่องหมายว่าดึงครบเพียงเพราะ process จบ

อย่ารันพร้อมกับ `src.backfill_traffy` หรือสั่งดึงวันเดียวกันจากอีก terminal
ตัวรันมี `runner.lock` ป้องกันการเริ่มซ้ำสำหรับ run directory เดียวกัน
หากเครื่องดับหรือ process ถูกปิด ให้ตรวจว่า PID ใน lock ไม่ทำงานแล้วก่อนนำ lock ที่ค้างออก

## ดูความคืบหน้าและหยุดอย่างเรียบร้อย

```powershell
Get-Content data/checkpoints/traffy/runs/full_history/progress.json -Raw
Get-Content data/checkpoints/traffy/runs/full_history/events.jsonl -Tail 5
```

`previously_verified_days` คือวันที่มีข้อมูลซึ่งตรวจแล้วก่อนเริ่มรอบนี้
`completed_dates_this_run` คือวันที่ตัวดึงทำสำเร็จในรอบปัจจุบัน
ระหว่างทำงาน `range_complete` ยังคงเป็น `false` จนกว่าจะตรวจครบทั้งช่วงอีกครั้ง

หากต้องการหยุด ให้สร้างไฟล์ต่อไปนี้ ตัวรันจะรอให้วันที่กำลังทำอยู่เสร็จก่อนหยุด:

```powershell
New-Item data/checkpoints/traffy/runs/full_history/STOP -ItemType File -Force
```

นำไฟล์ `STOP` ออกก่อนเริ่มรอบถัดไป เมื่อพื้นที่ว่างเหลือต่ำกว่า 2 GiB
ตัวรันจะสร้างไฟล์นี้เองเพื่อหยุดหลังงานที่กำลังทำเสร็จ

บน Windows การอ่านไฟล์สถานะหรือโปรแกรมสแกนไวรัสอาจล็อกไฟล์ชั่วคราว
ตัวรันจะลองเขียนสถานะใหม่โดยยังเก็บ JSON ฉบับก่อนหน้าไว้ และจะไม่หยุดงานดึงเพราะไฟล์สถานะล็อก

## ตรวจผลส่งมอบ

```powershell
python -X utf8 -m scripts.run_traffy_backfill --start 2022-06-01 --end 2026-11-08 --audit-only
```

ผลอยู่ที่ `evidence/traffy/full_backfill/summary.json` โดยต้องได้
`range_complete: true`, `verified_days: 1622` และ `gap_count: 0` จึงถือว่าครบช่วงที่ขอ
ตัวตรวจอ่านไฟล์จริงเพื่อตรวจทั้งข้อมูลทุกประเภทและชุดน้ำท่วม ตรวจจำนวนและ hash
เลขรอบการรัน วันตามเวลาไทย รายงานซ้ำภายในวัน ตัวหารที่ยังเก็บรายงานทุกประเภท
ไฟล์ดิบที่อ้างอิง และหน้าว่างสุดท้ายจาก API

เมื่อไม่มี runner ทำงาน สามารถใช้ `--audit-only` ตรวจซ้ำได้โดยไม่เรียก API
ระหว่างดาวน์โหลดให้ใช้ `progress.json` เพราะ lock ป้องกันการ audit ทับงานใน run directory เดียวกัน

การครบ 1,622 วันหมายถึงครบทุก partition ที่ขอจากข้อมูลที่ endpoint ส่งกลับ
API ยังคงแจ้งยอดรวมมากกว่าแถวที่เข้าถึงได้ในบางช่วง คำเตือนนี้จะคงอยู่ในหลักฐาน
จึงไม่ใช่การยืนยันว่าได้รายงานทุกชิ้นตามยอดที่ต้นทางแจ้งหรือทุกเหตุการณ์น้ำท่วมจริง

ไฟล์ข้อมูลดิบและข้อความรายงานยังอยู่ในพื้นที่ `data/` ที่ไม่ commit
ไฟล์หลักฐานมีเฉพาะจำนวน สถานะ วันที่ ค่า hash และข้อมูลติดตามการดึง
