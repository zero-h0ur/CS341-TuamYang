## Summary

เพิ่มระบบ Traffy Data Ingestion สำหรับ Checkpoint ของโครงการ TUAMYANG
รองรับการดึงรายงานรายวัน การอัปเดตรายชั่วโมงในช่วงฝนหนัก และการดึงข้อมูลย้อนหลังตั้งแต่กลางปี 2565
พร้อมกติกากรองน้ำท่วมจากข้อความ การแปลงเวลา UTC เป็นเวลาไทย และหลักฐานทดสอบจากข้อมูลจริงบนเครื่อง

ระบบเก็บข้อมูลดิบสำหรับตรวจสอบย้อนหลัง ตัดรายงานซ้ำด้วย `ticket_id`
และเก็บรายงานทุกประเภทไว้เป็นตัวหารสำหรับการวิเคราะห์ Q2
งานของสมาชิกคนที่ 2 รวมถึงการแก้ไขจาก PR #9 อยู่ใน `feature/ingest-traffy` และ PR นี้ทั้งหมดแล้ว

  แบ่งผลเป็น `flood`, `non_flood`, `uncertain` พร้อมเหตุผลและเวอร์ชันกติกา

## Deployment Boundary

- **ยังไม่ได้ deploy/เรียก Lambda บน AWS หรือเขียนข้อมูลลง S3 จริง**
  ผลการดึงข้อมูลจริงเป็นการรัน Local ส่วนการทดสอบ deploy ใช้ AWS mock
  มีสคริปต์และตารางรันเตรียมไว้แล้ว แต่ยังต้องแนบหลักฐานจากบัญชี AWS ของทีม
- Backfill รองรับช่วงตั้งแต่กลางปี 2565 แต่ยังไม่ได้ดาวน์โหลดครบทั้งช่วง
  ผล 794 รายงานเป็นการทดสอบย้อนหลังจริงเพียงหนึ่งวัน
- API ที่ทดสอบรับช่วงเวลาเป็นวันที่ UTC และแจ้งยอดรวมมากกว่าแถวที่ส่งกลับจริง
  โดยต่างกัน 40/47/69 รายการในสามวันของกรณีศึกษา ระบบอ่านจนพบหน้าว่างและบันทึกความต่างไว้
  ยังไม่ถือว่าดึงครบตามยอดที่ API แจ้ง เวลาแจ้งรายงานและผลกรองข้อความยังไม่ยืนยันเวลาเริ่มท่วมหรือน้ำท่วมที่บ้าน
- PR นี้ใช้ `feature/ingest-thaiwater` เป็นฐานสำหรับ shared storage
  เมื่อฐานเข้า `main` แล้วให้เปลี่ยนฐาน PR ตาม หาก merge แบบ squash ให้ย้ายเฉพาะ commit ของ Traffy
  ไปต่อบน `main` ก่อน เพื่อป้องกันประวัติงานฐานซ้ำซ้อน

## Downstream Handoff

- **Reference & Spatial Join:** ใช้รายงานจาก `incoming/traffy/` โดยจับคู่พื้นที่จาก
  `longitude` / `latitude` และอ้างอิง `ticket_id` รายงานที่พิกัดขาดหรือผิดรูปแบบยังถูกเก็บไว้พร้อม
  `quality_flags` เพื่อให้วัดสัดส่วนที่ join สำเร็จได้
- **Orchestration & Validation:** รอ manifest เป็น `SUCCESS` และตรวจว่า `batch_id`
  กับ `records_sha256` ตรงกับข้อมูลก่อนประมวลผลต่อ หาก S3 event มาก่อน manifest ให้รอหรือลองใหม่
  manifest นี้เป็น ingestion checkpoint ส่วน `_SUCCESS.json` ของขั้นตอนถัดไปเป็นหน้าที่ orchestration
- **Curated & Analysis:** ใช้ `report_date_bkk` / `report_hour_bkk` รวมรายชั่วโมง
  นับ `is_flood_report IS TRUE` เป็นตัวเศษ เก็บรายงานทุกประเภทเป็นตัวหารของ Q2
  และแสดงจำนวน `uncertain` แยกต่างหาก ไฟล์ `staged/traffy/` มีเฉพาะรายงานน้ำท่วม จึงใช้หาตัวหารไม่ได้

รายละเอียดโครงสร้างข้อมูลและเงื่อนไขส่งต่ออยู่ใน `reference/traffy_schema_contract.md`
