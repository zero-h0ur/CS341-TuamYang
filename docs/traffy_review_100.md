# ตรวจตัวอย่าง Traffy 100 รายงาน

ตัวอย่างเดิมสุ่มจาก 9,614 รายงานในวันที่ไทย 24–26 ก.ย. 2569 ด้วย seed `341`
ผลอ่านโดย AI และผลคำนวณอยู่ใน `evidence/traffy/review_100.json`
ส่วนผลตรวจโดยคนยังไม่มีการกรอก ระบบไม่เปลี่ยนผล AI ให้เป็นผลตรวจของคน

## ไฟล์สำหรับอ่านและกรอกผล

เปิด `data/review/traffy/human_review_100_with_text.json`
ไฟล์นี้รวมข้อความของตัวอย่างเดิมเข้ากับช่องกรอกผลไว้ด้วยกัน และไม่มีผลทำนายจากกติกาให้เห็น
แบบฟอร์มเดิม `human_review_100.json` ยังคงอยู่ ไม่ถูกเขียนทับ

กรอก `reviewer_name` เป็นชื่อผู้ตรวจ แล้วอ่านครบ 100 รายงาน โดยกรอกแต่ละรายการดังนี้:

- `label`: `flood` เมื่อข้อความบอกว่ามีน้ำท่วมหรือน้ำขัง, `non_flood` เมื่อเป็นเรื่องอื่น
  หรือกล่าวถึงการป้องกัน/ปฏิเสธโดยไม่มีข้อความยืนยันน้ำท่วม และ `uncertain` เมื่อข้อความยังไม่พอตัดสิน
- `rationale`: เหตุผลสั้น ๆ ว่าข้อความส่วนใดทำให้เลือกผลนั้น

ใช้เฉพาะข้อความของผู้แจ้งใน `description` ไม่อาศัยผลกติกาหรือบันทึกแก้ปัญหาที่เกิดภายหลัง
หากข้อความกำกวมให้เก็บ `uncertain` ไว้ ไม่บังคับเลือกเพื่อให้คะแนนดีขึ้น
เมื่ออ่านและกรอกครบจริงจึงเปลี่ยน `status` จาก `pending` เป็น `completed`

## คำนวณผลจากการตรวจ

```powershell
python -X utf8 -m scripts.review_traffy evaluate --labels data/review/traffy/human_review_100_with_text.json --output-dir evidence/traffy/human_review
```

คำสั่งจะตรวจชื่อผู้ตรวจ สถานะ รายงานครบตามตัวอย่างเดิม เหตุผล และความตรงกันของข้อมูลต้นทางก่อนคำนวณ
หากรายงานที่กติกาจัดเป็นน้ำท่วมยังมีผลอ้างอิง `uncertain` จะยังแสดงขอบเขตของ precision
แทนการตัดรายการเหล่านั้นทิ้งเพื่อแสดงคะแนนเต็ม

ไฟล์ข้อความเต็มและแบบฟอร์มใน `data/review/traffy/` ไม่ถูก commit
ผลใน `evidence/traffy/human_review/` จะเกิดขึ้นเมื่อมีการตรวจโดยคนจริงและรันคำสั่งสำเร็จเท่านั้น
